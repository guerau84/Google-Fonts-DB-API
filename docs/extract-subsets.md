# Plan: `extract-subsets.ts` — Generate `src/data/subsets.json`

## Context

- Source: `src/data/fonts.json` (array of **2022** fonts), generated by `docs/organize-fonts.md`.
- Target: `src/data/subsets.json` (currently empty, scaffold). Do not touch `src/data/fonts.json`, `src/categories.ts`, etc.
- Goal: extract every script subset (`subsets[]` per font) into a lightweight index of `{ id, name, count, families }`.
- Only this plan MD is delivered in this task; the implementation is left for the next one.

## Data notes (verified against `fonts.json`)

- Each font has `id` and `subsets: string[]`. **2017** fonts carry the internal `"menu"` subset — it is **excluded** from the output (it is not a real script).
- Remaining unique subsets: **181** (e.g. `latin`, `latin-ext`, `vietnamese`, `cyrillic`, `cyrillic-ext`, `greek`, `math`, `greek-ext`, `symbols`, `japanese`, `devanagari`, `hebrew`, plus ~170 one-off script subsets with count 1, e.g. `ahom`, `yezidi`, `znamenny`).
- Largest by family count: `latin` 1875, `latin-ext` 1548, `vietnamese` 537, `cyrillic` 307, `cyrillic-ext` 244, `greek` 128.

## Format decision

The request shows an example whose schema uses a `categories` key (a copy of the categories format). Since this file aggregates **subsets**, the plan uses the analogous structure keyed on `subsets`; every other field (`id`, `name`, `count`, `families`, `total`) matches the requested format 1:1.

## Output format

```json
{
  "subsets": [
    {
      "id": "latin",
      "name": "Latin",
      "count": 1875,
      "families": ["42dot-sans", "abeezee", "abel", "abhaya-libre", "aboreto"]
    },
    {
      "id": "latin-ext",
      "name": "Latin Ext",
      "count": 1548,
      "families": ["abeezee", "abhaya-libre", "aboreto", "advent-pro", "afacad"]
    },
    {
      "id": "ahom",
      "name": "Ahom",
      "count": 1,
      "families": ["ahom"]
    }
  ],
  "total": 181
}
```

### Rules

| Point | Decision |
|---|---|
| `id` | subset string as-is from `fonts.json` |
| `name` | title-case each hyphen-separated token (`latin-ext` → `Latin Ext`, `cyrillic-ext` → `Cyrillic Ext`, `latin` → `Latin`) |
| `count` | number of fonts that list the subset |
| `families` | font `id`s, in source order (i.e. order of appearance in `fonts.json`) |
| `menu` | excluded from the index |
| Order | `count` descending, then `id` ascending (deterministic, stable across runs) |
| `total` | `subsets.length` (181) |

## Proposed implementation in `src/scripts/extract-subsets.ts`

1. **Paths** (relative to the project root):
   - `SRC = src/data/fonts.json`
   - `OUT = src/data/subsets.json`
2. **Read**: `readFile` + `JSON.parse` of `fonts.json`. If missing or corrupt, abort with an error.
3. **Aggregate** with a `Map<subset, string[]>`:
   - For each font, for each subset in `font.subsets`, if `subset !== 'menu'`, push `font.id` into the map entry.
4. **Build entries**: `{ id, name: toTitleCase(id), count: families.length, families }`.
5. **Sort**: by `count` desc, then `id` asc.
6. **Write**: `JSON.stringify({ subsets, total: subsets.length }, null, 2)` + trailing newline.
7. **Logging**: total subsets written, `menu` excluded count.
8. **Entrypoint**: `main()` with `await`, ESM; run with `npx tsx src/scripts/extract-subsets.ts`. No changes to `package.json`.
